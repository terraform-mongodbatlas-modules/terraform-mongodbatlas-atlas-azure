# Upgrade Guide: v0.2.x to v0.3.0

- [Configurable Timeouts](#configurable-timeouts)

## Configurable Timeouts

v0.3.0 introduces a `timeouts` variable with `create`, `update`, and `delete` fields defaulting to `"30m"`. The module applies these timeouts to each wrapped resource where the Terraform provider exposes a `timeouts` block or, for `mongodbatlas_encryption_at_rest_private_endpoint`, a `timeouts` attribute on the resource.

### Who is affected?

**Existing deployments upgrading from v0.2.x** that use the default `timeouts` configuration (unset, `timeouts = {}`, or a partial object that still applies module defaults) will see a plan diff on the **first** `terraform plan` (or `apply` plan) **after** you bump the module to v0.3.0. The diff is the new `"30m"` module-managed timeout settings where the previous module version did not set timeouts. The change is an in-place update, not a forced replacement: Terraform updates timeout metadata in state; it does not destroy infrastructure solely because of this diff. If you set `timeouts = null` before that first plan, the module does not add those blocks, so you avoid the diff; see [Zero-diff upgrade](#zero-diff-upgrade) below.

### Why the change?

PrivateLink and encryption private endpoint operations can fail or stall. The default long waits in the provider are often longer than teams want. A single `timeouts` object with practical defaults (and the option to keep provider defaults) gives predictable behavior without per-resource variables.

### Zero-diff upgrade

Set `timeouts = null` to skip all module-managed timeout blocks and attributes and keep each provider’s own defaults.

```terraform
module "atlas_azure" {
  source  = "terraform-mongodbatlas-modules/atlas-azure/mongodbatlas"
  version = "~> 0.3"
  # ...
  timeouts = null
}
```

After you upgrade the module source to v0.3.0:

1. Run `terraform plan` with `timeouts = null`. The plan should not add or change module-managed `timeouts` blocks.
2. Run `terraform apply` if you are ready to align state with that configuration.

When you want the 30m defaults (or custom values), remove `timeouts = null` or set `timeouts = {}` for the default 30m create, update, and delete values. You can also set a partial object; omitted keys use the 30m default for those operations.

```terraform
module "atlas_azure" {
  # ...
  timeouts = {
    create = "45m"
    # update and delete default to 30m
  }
}
```

For imported stacks and the `timeouts` input (including `timeouts = null` after import), see the `timeouts` variable description in the module reference.
