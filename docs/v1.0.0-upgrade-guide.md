# Upgrade Guide: v0.3.x to v1.0.0

- [encryption_client_secret removed (Breaking Change)](#encryption_client_secret-removed-breaking-change)

## encryption_client_secret removed (Breaking Change)

v1.0.0 removes the root `encryption_client_secret` variable and the encryption submodule's `client_secret`. v0.3.0 deprecated both in favor of secretless authorization based on the Cloud Provider Access `role_id`.

### Who is affected?

Deployments that set `encryption_client_secret` on v0.3.x are affected.

It does not affect deployments that leave it unset (the default).

### Required action

Remove the `encryption_client_secret` argument from the module block. The module needs no replacement: it authenticates through Cloud Provider Access `role_id` automatically.

```terraform
# Before (v0.3.x, encryption_client_secret deprecated)
module "atlas_azure" {
  source = "terraform-mongodbatlas-modules/atlas-azure/mongodbatlas"
  # ...
  encryption_client_secret = var.encryption_client_secret
  encryption = {
    enabled        = true
    key_vault_id   = azurerm_key_vault.atlas.id
    key_identifier = "https://my-vault.vault.azure.net/keys/my-key"
  }
}

# After (v1.0.0)
module "atlas_azure" {
  source = "terraform-mongodbatlas-modules/atlas-azure/mongodbatlas"
  # ...
  encryption = {
    enabled        = true
    key_vault_id   = azurerm_key_vault.atlas.id
    key_identifier = "https://my-vault.vault.azure.net/keys/my-key"
  }
}
```

What happens if you do not migrate? Terraform rejects the configuration with an "Unsupported argument" error (`An argument named "encryption_client_secret" is not expected here`), so the plan fails.

### Why the change?

Encryption authenticates through Cloud Provider Access `role_id`, which authorizes Atlas to use the Key Vault without a client secret. The legacy secret path kept an Azure AD secret in your configuration and in Terraform state, so v1.0.0 removes it and leaves no long-lived credential to store or rotate.

### State migration

None. The resource address does not change. A deployment that used the legacy secret sees an in-place update to the `mongodbatlas_encryption_at_rest` `azure_key_vault_config`: Terraform clears the secret and the legacy IDs and sets `role_id`. Apply the update to move Atlas to role-based authentication.
